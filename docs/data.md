# מבנה הנתונים

הנתונים נשמרים בגיליון **Kesher-4U — נתונים** ב־Google Drive. בגיליון שלוש לשוניות.

## לשונית "קריאות"

שורה אחת לכל קריאה. העמודות הגלויות:

| עמודה | תיאור |
|---|---|
| מס׳ קריאה | מספר רץ שמתחיל ב־1001 |
| נושא / תת־נושא | לפי `Config.gs`. בקריאת אירוע, תת־הנושא הוא מקום האירוע |
| מתחם / מבנה / פירוט מיקום | מיקום התקלה. בקריאת אירוע באולם קבוע העמודות האלה ריקות |
| מועד אירוע / בוקר/ערב | רק בקריאות אירוע. בוקר נשמר כשעה 08:00 וערב כשעה 18:00 |
| תיאור קצר / פירוט | הטקסט שהמדווח הזין |
| סטטוס | חדשה, בטיפול, ממתינה למדווח, סגורה. קריאה שנמחקה מסומנת "נמחקה" ומוצגת עם קו חוצה |
| דחיפות | נמוכה, רגילה, גבוהה, דחופה |
| נציג מטפל / מדווח / התקבל דרך | מי מטפל, מי דיווח ואיך הקריאה התקבלה |
| נפתחה / עודכנה / יעד / נסגרה | תאריכים. היעד של תקלה הוא מועד הפתיחה ועוד זמן לפי הדחיפות; היעד של אירוע הוא מועד האירוע |
| זמן טיפול (שעות) | מהפתיחה ועד הסגירה |
| יומן טיפול | כל העדכונים, שורה לכל עדכון |

**עמודות מוסתרות (לא לערוך):** `id`, `updated`, `deleted`, `json`. העמודה `json` מכילה את הרשומה המלאה, וממנה האתר קורא.

**יעדי טיפול לפי דחיפות:** דחופה 4 שעות, גבוהה 24 שעות, רגילה 72 שעות, נמוכה 7 ימים.

## לשונית "מדווחים"

לכל מדווח: שם, טלפון, יחידה או מחלקה, מייל והערות. כשפותחים קריאה, המערכת מחפשת מדווח קיים לפי מספר הטלפון ואחר כך לפי השם. אם לא נמצא, נוצר מדווח חדש.

## לשונית "יומן שינויים"

שורה לכל פעולה שבוצעה באתר:

| עמודה | תיאור |
|---|---|
| מועד | מתי הפעולה בוצעה |
| פעולה | יצירה, עדכון או מחיקה |
| סוג | קריאה או מדווח |
| מס׳ קריאה | |
| מזהה | |
| בוצע ע״י | השם שהנציג הזין בכניסה לאתר |
| סטטוס | הסטטוס אחרי הפעולה |
| נתונים (JSON) | עותק מלא של הרשומה אחרי הפעולה |

הלשונית מוגנת: אם מנסים לערוך אותה ידנית, מופיעה אזהרה. היומן לא נמחק לעולם, וגם אחרי מחיקת קריאה נשאר העותק האחרון שלה ביומן.
